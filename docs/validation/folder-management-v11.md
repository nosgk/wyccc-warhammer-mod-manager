# 文件夹视图与批量管理：实现与验证

基线：1.3.7（fcd21fa42f862589d65fcbf8d9af9a761a508bb0）。

## 行为

- 未启用和已启用列表各有独立的显示/隐藏文件夹开关，默认隐藏。隐藏后恢复原有 MOD 列表顺序，并清除该栏的文件夹筛选。
- 文件夹按当前界面语言的名称顺序放在顶部，数字使用自然排序；未归类 MOD 在下方保持原有相对顺序。中间栏也显示新建的空文件夹。名称排序覆盖历史手动位置，文件夹标题不再支持原生拖动排序。
- 中间栏顶部可以直接创建空文件夹；右键文件夹提供重命名、释放所有 MOD、删除并释放 MOD、删除并取消订阅。
- 中间栏文件夹右侧 + 批量启用，右侧栏 − 批量停用；复用已有播放集保存、依赖提示和单一归属机制。
- 释放成员只清空归属，保留空文件夹及 MOD 启用状态；删除并释放不取消订阅。
- 隐藏文件夹后的 MOD 拖动继续执行原有排序行为，不触发移出文件夹。
- 新增界面文案覆盖六种内置语言。

## 取消订阅

预览前等待待保存的播放集操作完成。预览显示工坊项目数、受影响的 MOD 名称、引用这些 MOD 的播放集，以及跳过的本地或缺失成员数量。同一工坊项目可能包含多个 Pack，因此影响清单包含该项目的所有已扫描 MOD。

后端生成一次性确认凭证，五分钟有效。执行前重新比较游戏、播放集、成员和影响范围；发生变化后拒绝旧确认。游戏运行时拒绝执行。取消订阅复用现有 Steam 操作；全部成功后删除文件夹并释放其余成员，部分失败则保留文件夹并显示逐项错误，以便重试。

自动化测试模拟 Steam 响应，不实际取消订阅。

## 验证

- 前端使用 node node_modules/vitest/vitest.mjs run --maxWorkers=2 --testTimeout=30000。默认五秒阈值会使原有的 2050 单位分页测试在本机超时，因此验证时提高阈值，未修改该测试源码。
- Vite 生产资源构建成功，存在既有的大于 500 kB 的资源块提示。
- pytest tests/test_mod_folders.py -q：18 项测试及 16 个子测试通过。覆盖归属持久化、释放成员、共享工坊 Pack 的影响范围、取消订阅成功与失败、确认过期与重用、上下文变更和游戏运行中阻止。
- 后端全量运行：921 通过、2 跳过、1 失败、256 子测试通过。失败为原有 Unicode 路径启动测试：模拟的 X: 盘在当前 Windows 环境不存在。用未修改的 HEAD API 复测同样失败，错误为 WinError 3。
- 文件夹视图测试覆盖两栏独立切换、名称排序、空文件夹置顶、重命名后重排、隐藏后恢复顺序及拖动行为，以及取消订阅确认前不执行操作。
- 用户已完成本地功能验收，确认符合需求。此确认不等同于每种 Steam 失败情形和所有游戏启动场景均已人工覆盖。
